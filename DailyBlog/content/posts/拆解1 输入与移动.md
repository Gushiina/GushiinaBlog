## 二、输入系统（Input System）

### 2.1 两种接入方式并存

- **现代方法**：`JammoActions.inputactions`（可视化配置，本质是 JSON）
- **兼容方法**：`PlayerMovement.cs`（传统 `Input.GetAxis` 式代码）

### 2.2 现代方法核心：Input Action Asset

可视化面板中配置了 5 种 Action，例如：
- **Move** → Type: `Value`（持续输出向量）
- **Attack** → Type: `Button`（单次触发）
![[Pasted image 20260515215146.png]]
### 2.3 Send Message 模式（本项目采用）

挂载链路：
```
Player Input 组件 → 引用 JammoActions.inputactions
                → Behavior 设为 Send Messages
```

**自动调用机制**：
- 当 `Move` Action 有输入时，Player Input 会自动在挂载的脚本上寻找名为 `OnMove` 的方法
- **命名铁律**：`Action 名` → `On + Action名`（如 `OnMove`、`OnAttack`）
- **方法签名**：必须接收 `InputValue value` 参数

> 💡 这不是 C# 反射遍历字段，而是 Input System 包内部维护的委托分发机制，性能远好于反射。

## 三、MovementInput.cs 逐层拆解

### 3.1 防御性编程：`[RequireComponent]`

```csharp
[RequireComponent(typeof(CharacterController))]
public class MovementInput : MonoBehaviour { }
```

**作用**：
- 仅对**编辑器**生效的元数据特性（Attribute）
- 拖拽脚本到 GameObject 时，若缺少 `CharacterController`，Unity **自动强制添加**
- 防止运行时空引用（NullReference）

**原理**：编辑器在序列化阶段检查组件依赖，不是运行时反射。

### 3.2 输入接收：`OnMove`

```csharp
public void OnMove(InputValue value)
{
    moveAxis = value.Get<Vector2>();
}
```

- 由 Send Message 模式自动驱动
- `moveAxis` 存储左摇杆 / WASD 的二维输入

### 3.3 输入处理核心：`InputMagnitude()`

```csharp
void InputMagnitude()
{
    float inputMagnitude = new Vector2(moveAxis.x, moveAxis.y).sqrMagnitude;

    if (inputMagnitude > 0.1f)
    {
        anim.SetFloat("InputMagnitude", inputMagnitude * acceleration, .1f, Time.deltaTime);
        PlayerMoveAndRotation();  // 实际移动+转向
    }
    else
    {
        anim.SetFloat("InputMagnitude", inputMagnitude * acceleration, .1f, Time.deltaTime);
    }
}
```

| 步骤                                     | 技术点           | 说明                             |
| -------------------------------------- | ------------- | ------------------------------ |
| ① `sqrMagnitude`                       | 长度平方          | `x² + y²`，省去 `sqrt` 运算，CPU 更友好 |
| ② `> 0.1f`                             | 死区（Dead Zone） | 过滤手柄轻微漂移/键盘抖动，**本质就是手柄适配**     |
| ③ `SetFloat(..., dampTime, deltaTime)` | 动画阻尼          | 4 参数版本，0.1 秒内平滑过渡，避免动画参数突变     |
| ④ `PlayerMoveAndRotation()`            | 实际位移          | 输入有效时才调用移动逻辑                   |

**为什么 `sqrMagnitude` 比 `magnitude` 好？**
- `magnitude = √(x² + y²)` 需要一次开方
- `sqrMagnitude = x² + y²` 直接可得
- 既然只是和 `0.1f` **比大小**，两边都不开方结果等价，性能更优

### 3.4 状态兜底：`OnDisable()`

```csharp
private void OnDisable()
{
    anim.SetFloat("InputMagnitude", 0);
}
```

**必要性**：
- `OnMove` 只在**有输入时**调用，正常松手后 `moveAxis` 自然归零
- 但如果脚本被**外部禁用**（如攻击时 `movementInput.enabled = false`），最后一帧动画参数可能卡在非零值
- `OnDisable` 强制归零，确保角色回到 Idle，防止动画"冻住"

## 四、动手实验记录

### 实验 1：观察输入值变化
- 单按 W/A/S/D：输出对应轴向的单位向量（如 `(0, 1)`）
- **W+D 同时按**：输出 `(1, 1)`，其 `sqrMagnitude = 2`，`magnitude = √2 ≈ 1.414`
- 不按任何键：值为 `(0, 0)`

> 注：Input System 默认会对摇杆/键盘向量进行**归一化**，保证斜向移动速度不会过快。

### 实验 2：添加 Jump 动作
**配置流程**：
1. 双击 `JammoActions.inputactions` → Player Action Map → `+` 添加 Action
2. 命名 `Jump`，Type 改为 `Button`
3. Bindings 绑定 `<Keyboard>/space`
4. 代码中添加：
   ```csharp
   public void OnJump(InputValue value)
   {
       Debug.Log("Jump pressed!");
   }
   ```

**进阶问题：如何实现真正的跳跃？**
- 目前只是打印日志，真实跳跃需要：
  - 检测 `isGrounded`（CharacterController 自带属性）
  - 给垂直速度 `velocity.y` 赋一个向上的初速度
  - 在 `Update` 中持续施加重力 `velocity.y += gravity * Time.deltaTime`
  - 通过 `controller.Move(velocity * Time.deltaTime)` 应用位移

### 实验 3：验证 OnDisable
- 按住 W 奔跑时，Inspector 中取消勾选 `MovementInput`
- 观察：角色动画应**立刻回到 Idle**
- 若去掉 `OnDisable`：动画可能卡在最后一帧的奔跑状态，直到重新启用

> 用户反馈：零基础时肉眼难以区分，且受击后脚本状态会被外部系统重置，说明项目中已有其他逻辑在管理组件启用/禁用。

## 五、核心概念 Q&A

| 问题 | 答案 |
|------|------|
| **Move 为什么是 Value，Attack 为什么是 Button？** | Move 需要**持续输出**向量值（摇杆偏移量/WASD状态），Attack 只需要**单次触发**事件（按下即触发，不需要持续值）。 |
| **OnMove 为什么会被自动调用？** | Player Input 组件 + Send Messages 模式 + 命名约定 `On + ActionName`。Input System 内部分发，非反射。 |
| **RequireComponent 不加会怎样？** | 可能忘记挂 `CharacterController`，运行时报空引用；或代码中手动 `GetComponent` 为 null，导致移动逻辑失效。 |
| **sqrMagnitude 优化原理？** | 比较大小只需平方值，避免 `sqrt` 浮点运算。死区判断、距离比对场景下的经典优化。 |

## 六、CharacterController 与运动体系

### 6.1 什么是 CharacterController？

Unity 提供的**胶囊体角色移动器**，特点：
- **自带碰撞**：无需 Rigidbody，自动处理墙壁/地面
- **手动驱动**：代码直接控制位移，不受物理力影响
- **地形适配**：自动爬坡、上台阶、沿斜面滑行
- **胶囊体形状**：固定不可改

### 6.2 两条运动路线对比

| 维度 | CharacterController 路线 | Rigidbody 路线 |
|------|--------------------------|----------------|
| **驱动力** | 你直接控制（Kinematic） | 物理引擎控制（力/速度/扭矩） |
| **碰撞响应** | 简单阻挡 | 完整物理（反弹、摩擦、质量） |
| **斜坡/台阶** | 自动处理 | 需自行实现 |
| **物理交互** | 弱（推不动箱子、会穿模） | 强（可撞飞、被推动） |
| **手感** | 精准、跟手 | 真实、有惯性 |
| **适用** | 人形角色（FPS、ACT） | 载具、布娃娃、物理谜题 |

### 6.3 实战中的"双模式"

很多项目会**同时挂载两套系统**，按需切换：
- 正常移动 → `CharacterController`（精准控制）
- 被炸飞/击倒 → 切到 `Rigidbody`（物理受击反馈）
- 死亡 → Ragdoll（完全物理布娃娃）

> 本项目当前阶段属于**纯 CharacterController 路线**：输入直接驱动位移，没有质量、惯性、力的概念。

## 七、Unity 架构本质

**Entity-Component 架构**：
- `GameObject` = 空壳容器（Entity）
- `Component` = 功能模块（渲染、碰撞、脚本、音频…）
- 引擎通过**序列化引用**将组件组装到同一个容器上

**不是反射驱动**：
- 编辑器 Inspector 确实用反射显示字段，但运行时组件查找（如 `GetComponent`）是引擎 C++ 层维护的组件列表查询，性能远高于反射。
- 编译期类型确定，运行时通过**引用组合**协作。

## 八、扩展思考

1. **手柄适配确认**：`sqrMagnitude + 0.1f 死区` 确实是标准的手柄摇杆适配，键盘是顺带兼容。
2. **向量归一化**：W+D 同时按的原始向量和为 `(1,1)`，Input System 内部会进行归一化，保证斜向速度不会变成 `√2` 倍。
3. **如何实现跳跃**：需在 `OnJump` 中触发垂直速度，结合 `controller.isGrounded` 和重力逻辑，通过 `controller.Move()` 应用。
4. **运动模式切换**：Unity 角色运动确实分两种模式（手动控制 vs 物理驱动），高级项目往往混用。
