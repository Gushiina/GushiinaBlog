#数组 #双指针 
**数组的实现**：
- 定长+连续内存：分配后数组长度便不再改变。
- vector类型实际上是规定了capacity作为实际的分配空间，而常说的size长度只是一个计数器。

**数组元素移除的实质**：
- 只是将有效元素进行移动覆盖掉无效元素而已。

**原地算法**：
- 没有开辟新的空间，而在原有的空间上进行操作的算法叫做原地算法。MIT的算法导论里对这种排序算法叫原地排序性算法。

**不同编程语言的编程实践**：
- 使用库函数，例如C++的迭代器配合remove，erase。
- 越是库函数能够一步到位的事情能被拿出来考察，就越说明这题考的不是你怎么调用库函数工具。
- 而且库函数本身也具有复杂度，这反应不出来你对时间复杂度的认识。你只是借用一个封装好的工具解决了问题。但考察的并不是你解决问题本身，而是你在逻辑上的理解。

**回到算法**：
- 但是面试算法考察的是你对算法逻辑的认识，所以一定要回到根本上来。
- 暴力法就是不断重复过程，用嵌套循环不断覆盖。时间复杂度较高，作为一个简单题这样还是尽量争取拿高分的好。 
---
**双指针的思路**：
- 用一层循环做了两层循环做的事情
- 思维的转换：暴力做法就是找到并且覆盖，而快慢指针的逻辑则是我不在关注我要删除什么元素，而是我会保留什么元素，直接把我需要的结果覆盖到相应的位置上。
- 逻辑：快指针负责遍历寻址，每次移动后都判断这个元素是不是我需要的元素，而慢指针负责指出下一个要存放这个有效元素的位置在哪。

**代码的实现**：
```C++
class Solution {

public:

    int removeElement(vector<int>& nums, int val) {

        int len = nums.size();

        int fast = 0;

        int slow = 0;

        while (fast < len && slow < len) {

            if (nums[fast] != val) {

                nums[slow] = nums[fast];

                slow++;

                fast++;

            } else {

                fast++;

            }

        }

        return slow;

    }

};

```
- 一般对于双指针的情况为了灵活的变动，我个人更倾向于使用while循环的做法，因为这样我会更敏感度的关注到下标的变化。
- **返回值是slow而不是另外的计数变量k**，这其实是一个先斩后奏的问题，一般情况下你也不会直接感受到，当你真的去写了个k去计数再回看代码的时候你才会发现：你在模拟的是在原来的空间上建立一个新的数组的过程，所以你每添加一个元素 slow就前进1，slow代表的前进次数就代表了你新数组的长度，直接返回slow就好了

**总结**：双指针法移除数组元素，用一次循环和一对快慢指针，通过判断取舍和原地搭建，仅用$O(n)$的复杂度移除了整个数组的目标元素。

**对刷题思考**：
- 刷题提供了一个母题情景，之后面对复杂的情景将会是这些情景的组合。
- 看《代码随想录》实际上只是一个解题技法大全，只是讲解这些技法怎么用，但是并不能直接让我学会为什么要这样思考去构造算法。刷题本身也是如此。他只是告诉了你 **如何解决** 但并没有解决那个 **为什么这样做** 的问题。
**对算法的思考**：
- 承上，这其实是一个先斩后奏的做法，对于一个本科学生，他的时间是很有限并且金贵的，想要深度的解决 **为什么这样思考** 的问题并不那么轻松。
- 已有的算法设计即算法技巧都是前人所提出，实际上现代人是站在 伟人的肩膀上的。这些算法已经跳脱出了他们那时的历史环境，可以说的上是那时候的计算机发展面临着什么样的情况和问题，才会诞生出如此之多的设计，而随着不断人性化的迭代，这些细枝末节的思考诞生的条件也随之消匿了。**算法的学习，实际上是看着已经有的算法进行“事后诸葛亮”的思考。** 对于这个情况我们没有办法直观的再感受到“为什么”，只有对于算法本身和计算机基础以及它的发展历程进行系统性的学习，这是一个漫长的过程。想要逆推是很困难的，而更深入的学习也要花费更多的时间成本。
- **我们必须采取更高效的策略** ，对于现在而言，首先要解决的是**就业**的实际问题。先搞定**How to solve**
- 那么系统的算法思想是否是一个必需品呢？在我看来我的回答是对的。
- 做出了题目，学到了处理技巧，这只是解决了快速写出已经存在的算法的问题(即应试)，但是我们是要面对很多未知的问题(对站在真正意义上的开发来说)，写出以往并不存在的算法。也就是回到了**为什么**的角度上。
- 弄清楚为什么，才能面对真正的**How to solve**
