链表刷题总结

我感觉链表这一篇最难的不是各种操作，而是操作的条件很容易犯错。

特殊情况的优先处理

我个人认为需要尤其关注的几点：

  1. 头节点为空的情况
  2. 只有一个节点的情况
  3. 当基本的操作节点为k个，只有k-1个节点的情况
  4. 面对奇偶数个节点空判条件不同的情况

以上这几个情况基本都可以归纳成几个方法：

  1. 优先考虑dummy节点的引入能让问题1 2 3 化为一个模型中普适性的问题。
  2. 对于问题1，很多情况下专门处理
  3. 对于问题2，在处理问题1后进行处理，问题3实际上是问题2普适性的情况，·
    1. 很常用的一个条件是
    2. p->next != nullptr && p->nxet->next != nullptr
      对于合取逻辑运算，语言的计算方法是从左到右算，这几个问题都是指的是，因为当前位置的节点实际上是NULL的情况下，尝试去访问next字段引发的解空引用的未定义行为。
    3. 不过这条语句判断的前提也是建立在p是否为空的情况下。
    4. 思考方式就是：当前p所指的是否为空，他的下一个是否为空，下一个不是空的情况下下一个是不是空。

关于while循环的条件：

  • 选择while(p!=nullptr)，还是while(p->next!=nullptr)呢？
  • while(p!=q)的情况下要注意什么呢？

回答：

  • 总是优先选择p本身作为判断的条件，因为p->next语句本身没有检查作用，总是会出现未定义行为的可能性。选择判断p本身是否为空，总是黄金法则，遇到特殊情再具体考虑。
  • 以p和q的相等情况，往往是求节点问题的时候，或者成环问题的时候。那就是，如果p和q本身的起点地址相同，那么直接写while是不会执行的。至少执行一次的情况需要选择do...while
  • 还需要考虑的情况，就是p和q最后会不会相等，相等有两个情况
    • p和q位于相同地址，以及p和q最后都到达了NULL
  • 多多关注一下死循环的风险

关于倒数，顺数，长度，步数的数量关系问题：

  • 第i个的索引是i-1
  • 倒数第i个，就是顺数第size - i +1个，索引是 size - i
  • 倒数第i个到达最后一个节点是i-1步，如果使用快慢指针，快指针要比慢指针多走i步，慢指针才会指向它本身
    • [0] -> [1] -> [2] -> [3] -> NULL中，倒数第2个是[2]和最后一个节点相差了2 - 1 = 1步，而快指针比慢指针多走i步的时候，快指针已经到达NULL，慢指针才会指向[2]
  • 从第m个节点到n个节点，要走 n - m 步，例如从第一个节点走到第三个节点要走 3 - 1 = 2步
  • 从第m个节点到n个节点，隔了 n - m - 1 个节点
  • 总之，反复注意 第...节点是从1开始数的，如果你要使用的是下标，就弄清是第几个的时候减去1
  • 多画图先用步数思考，在转换成个数问题，统一思考避免边错

循环三要素：

  • 初值，条件，趋势

设计循环不变量，
循环不变量的三个性质：

  • 初始化：第一次迭代前条件成立
  • 保持：一次迭代前成立，那么对于下一次迭代前也是要成立的。
  • 终止：循环结束的时候，不变量能帮助我们证明算法的正确结果。

例子：

  • 设计区间规则（左闭右闭，或者左闭右开，中途不能变更这个判断的标准）
  • 指针的行进方式（一步？两步？）

用状态转移的设计 来替代 if判断分支混乱：

  • 这是一个思考维度的变化，就是从简单的逻辑判断跃迁到状态的改变
  • 去思考对象改变时对应的 有限状态自动机（状态转移条件）

适当的使用三目运算符替代if语句使整体更易读
例如：
检测环状链表的时候，指针p位移


p = (p!=nullptr)?p->next:nullptr;

输入p的当前状态，若p本身就是空指针了，依旧让他是空指针，若p不是空指针的情况下，说明他是存在后继（或者后继为NULL）的，可以向指针域对应的地址移动
